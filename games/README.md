# SPI 用語集（単語タイピングゲーム）

`rakuraku-entry.com/game` に置く、SPI に出る言葉をタイピングで覚えるゲーム集。
仕組み（ベルトコンベア・ローマ字の判定・結果・スマホの 4 択）は共通で、ゲームごとに違うのは **設定と言葉のリスト** だけ。

```
games/
  build.mjs          … ページを書き出すスクリプト（言葉のチェックもする）
  template.html      … 各ゲームのページのひな形
  words.html         … 各ゲームの単語一覧（/game/<slug>/words）のひな形
  hub.html           … ゲーム一覧（/game）のひな形
  spi-goi/
    game.json        … 設定（題名・コース・カードの名前など）
    words.json       … 言葉のリスト
site/game/
  engine/            … 共通のエンジン（romaji.js・game.js・game.css）。ここは手で直す
  index.html         … ゲーム一覧（書き出し）
  spi-goi/           … 各ゲーム（書き出し。手で直さない。words/ は単語一覧）
```

## 新しいゲームを足す

1. `games/spi-goi` をコピーして、フォルダ名を URL にしたい名前にする（半角の小文字・数字・ハイフン。例：`games/it-yougo` → `/game/it-yougo`）
2. `game.json` を書きかえる
3. `words.json` に言葉を入れる
4. 書き出す

   ```bash
   node games/build.mjs
   ```

5. 手元で確かめる（`worker/` で `npx wrangler dev --port 8788` → http://localhost:8788/game ）
6. いつもどおり `worker/` で `npm run deploy`（公式サイトと一緒に公開される）

## game.json

| 項目 | 中身 |
| --- | --- |
| `title` | ゲームの名前（シェアの文にも使う） |
| `seoTitle` / `description` | 検索結果に出る題名と説明 |
| `ogImage` | SNS でシェアされたときの画像（`/images/...`。なければ公式サイトと同じ画像） |
| `aboutHeading` / `aboutText` | スタート画面の下の説明（検索から来た人向け。なければ「〇〇とは」と `description`） |
| `listTitle` / `listDescription` / `listHeading` / `listLead` | 単語一覧のページの、検索結果に出る題名と説明・見出し・リード文（なければ題名から作る） |
| `summary` | ゲーム一覧のカードに出る一言 |
| `kicker` / `heading1` / `heading2` | スタート画面の小見出し・見出し 2 行 |
| `card` | ベルトに流れるカードの名前（例：`ES`、`名刺`） |
| `hashtags` | シェアのハッシュタグ |
| `courses` | コース。`levels` に入っている `lv` の言葉が出る。`cross` は ES がベルトの端から端まで流れる秒数（＝ 1 語を打てる時間。9〜13 くらい。時間がたつと少しずつ速くなる） |
| `levelNames` | 単語帳で言葉を分ける見出し（`lv` ごと。なければ「レベル 1」など） |
| `defaultCourse` | 最初に選ばれているコースの番号（0 から） |
| `ranks` | 称号。`[1 分あたりの点数, 称号]` を高い順に（なければ「マスター」などになる） |
| `order` | ゲーム一覧での並び（小さいほど先） |

## words.json

```json
{ "w": "義憤", "y": "ぎふん", "m": "不正や不道徳に対して抱く怒り",
  "e": "不正の報道に義憤を覚える", "p": "義憤を覚える", "pr": "ぎふんをおぼえる", "lv": 2 }
```

| 項目 | 中身 |
| --- | --- |
| `w` | 言葉 |
| `y` | 言葉の読み（ひらがな） |
| `alt` | ほかの読み（あれば。例：端緒 → `["たんちょ"]`）。どちらで打っても正解 |
| `syn` | 意味の近い言葉（あれば。例：跋扈 → `["跳梁"]`）。意味の 2 択・4 択で、まぎらわしい選択肢として出さない。words.json にある言葉を書く（両方の言葉に書いておく） |
| `m` | 意味 |
| `e` | 例文（画面に全体を出す） |
| `p` | 打つ言い回し（例文の中にそのまま入っていること） |
| `pr` | 言い回しの読み（ひらがな。言葉の読みを含むこと） |
| `lv` | 難しさ（コースの `levels` と合わせる） |

## 単語一覧のページ

`build.mjs` は、言葉をすべて HTML に書き出した単語一覧（`/game/<slug>/words`）も作る。ゲームの言葉は JavaScript で読み込むので検索エンジンからは見えにくいが、このページは「〇〇 意味」などで探して来た人が読める。レベルごとに五十音順で並べ、言葉ごとにページ内リンク（`/game/spi-goi/words#逡巡`）がある。構造化データ（`DefinedTermSet` とパンくず）も入れている。

サイトマップの更新日は、中身が変わったページだけ書きかえる（毎回今日の日付にすると、検索エンジンが更新日を信用しなくなる）。

`build.mjs` は、次のどれかがあると何も書き出さずに止まる。

- 足りない項目・同じ言葉の重なり
- 言い回しが例文に入っていない、言葉が言い回しに入っていない
- 読みにひらがな以外がある
- 言い回しがローマ字で最後まで打てない
- `syn` に words.json にない言葉がある
- 言葉が 10 語より少ないコースがある

## 広告（Google AdSense）

`games/ads.json` に ID を入れて `node games/build.mjs` で書き出すと、広告が出る。`client` が空なら、広告のタグも ads.txt も出さない（いまの状態）。

```json
{
  "client": "ca-pub-1234567890123456",
  "slots": { "start": "1111111111", "play": "4444444444", "result": "2222222222", "side": "5555555555", "hub": "3333333333" }
}
```

| 項目 | 中身 |
| --- | --- |
| `client` | AdSense のサイト運営者 ID（`ca-pub-` ではじまる） |
| `slots.start` | スタート画面の下の広告ユニットの ID |
| `slots.play` | パソコンのプレイ中、ステージの下に出す小さい横長の広告ユニットの ID（スマホの 4 択の画面には出さない） |
| `slots.result` | 結果画面の下の広告ユニットの ID |
| `slots.side` | 結果画面のスコアの下（左の列）に出す縦長（280×560）の広告ユニットの ID。パソコンだけ。入れると、スコアのカードはスクロールしてもついてこなくなる（下の広告に重ならないように） |
| `slots.hub` | ゲーム一覧（/game）の下の広告ユニットの ID |

広告ユニットは AdSense の「広告」→「広告ユニットごと」→「ディスプレイ広告」で、レスポンシブのものを作る（`play`・`side` も同じ。大きさは `game.css` の `.ad-small`（728×90、画面が狭いと 468×60）と `.ad-side`（280×560）で決めている）。空の枠は出さない。

- `client` を入れると、`site/ads.txt` も書き出す（AdSense のサイトの確認にも使える）
- **自動広告はオフにする**（AdSense の「広告」→「サイトごと」）。オンにすると、ゲームの画面の上や 4 択のそばにも Google が広告を差し込み、誤クリックの扱いになりかねない
- 広告をゲームの画面に重ねたり、押す・タップする場所のすぐ近くに置いたりしない。遊んでいるあいだに時間で入れ替えない（どれも AdSense の規約違反）。スマホのプレイは 4 択をタップするので、プレイ中の広告はパソコンだけにしている
- 広告の一部を隠さない（`overflow: hidden` などで切らない）
- ヨーロッパからの閲覧向けに、AdSense の「プライバシーとメッセージ」で同意のメッセージ（GDPR）をオンにしておく
- プライバシーポリシー（`site/privacy.html` の「3. 広告について」）に、Google AdSense のことを書いてある。広告を出す場所を変えたら、そこも直す

## 気をつけること

- 意味と例文は自分の言葉で書く。本やサイトの文章をそのまま使わない（言葉そのものは使ってよい）
- 読みは辞書で確かめる。形態素解析（kuromoji など）で下書きしたときは、「〜心（しん）」「〜力（りょく）」などの読み違いが出やすい
